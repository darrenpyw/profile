With the recent advances in LLM technology, it is hard to deny its disruptive use cases such as coding, automation and soon, cyber security. In my experience with using LLMs, I have seen it hallucinate answers that did not exist at the point the model was trained on. When asked to provide an exploit code for a new CVE that was just released, the LLM cited a non-existent metasploit module. Additionally, frontier and free to use models like Claude, Gemini and ChatGPT placed restrictions on malicious usage. However this restriction can be easily bypassed by rephrasing the prompt as a cyber security professional seeking the help of the LLM to analyse and validate the vulnerability with a sample code snippet.

Hence the motivation to run a local LLM model to understand how it works under the hood and how to use AI assistants focused on cyber security tasks. This is the first of a series of blog posts to document the process and interesting discoveries in the learning journey.


## Hardware

The hardware is a used gaming laptop from Carousell. The spec is not great but it will run some smaller sized models.

- Asus TUF Gaming F15 Laptop
- RTX 3060 Laptop GPU
- 6GM VRAM
- Windows 11 Home Edition
- 48 GB system RAM

## Installing llama.cpp

The official releases is available on Github at https://github.com/ggml-org/llama.cpp/releases. Alternatively, install it with winget. This installs the llama.cpp Vulkan version.
```cmd
winget install llama.cpp
```

Start llama.cpp server to check if things are working. Here I'm using one of the model previously downloaded for Ollama.
```cmd
llama-server -c 32768 -m "C:\Users\User\.ollama\models\blobs\sha256-60e05f2100071479f596b964f89f510f057ce397ea22f2833a0cfe029bfc2463"
```

The web ui is running on http://127.0.0.1:8080/ locally and can be used to chat with the LLM. For security, this web interface must not be exposed to the public internet without authentication. TLS encryption can be enabled if llama server is used in an internal enterprise setting.

## Model Selection 

With the GPU's limited VRAM size, the model selected will have to fit in the 6GB VRAM or lower to account for context size.

In the previous step, llama server is started using a model file previously downloaded using Ollama. There are other models available for download from Hugging Face using the -hf flag.

```cmd
llama-server -hf Jackrong/Qwen3.5-4B-Claude-4.6-Opus-Reasoning-Distilled-GGUF
```

## Benchmarking llama-bench CUDA vs Vulkan
Curious about the performance difference between Vulkan and Cuda, I downloaded the CUDA build from https://github.com/ggml-org/llama.cpp/releases and ran llama-bench.

Vulkan shows lower prompt processing performance with insignificant advantage in terms of token generation score compared to the CUDA build.

## What Next?

The GPU's VRAM is the bottleneck in terms of the model and context size to handle big tasks like coding an entire SaaS application. Hopefully with bite sized tasks, it is sufficient to perform the following tasks:
- Coding agents
- Pentest agents
- Threat intelligence gathering and summarization
